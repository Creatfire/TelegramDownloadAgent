# TG Agent v1.2 测试文档

> 给负责测试的 AI（Claude Code / Codex / ZCode 等）或人工测试者使用。只做**基本功能验证**，不做压力、冒烟或极限场景测试。
>
> ⚠️ 测试使用的是用户的**真实 Telegram 账号**，请遵守：
> - 每次读取用小的 `limit`（≤ 20）；不要循环翻页扫描大频道；不要并发发起大量调用。
> - 下载只测 1～2 个 **小于 20 MB** 的文件。
> - 同一个用户名不要反复解析（Telegram 对用户名解析限流很严）；拿到数字 ID 后改用 ID。
> - 不要尝试任何写操作。账号登录、批准下载、批准订阅都由用户在控制台完成，测试者不要代办。

## 0. 前置条件

| 项 | 检查方法 |
|---|---|
| 服务已启动 | 用户运行 `start.bat` / `start.sh` / `tg-agent`；打开启动窗口里打印的 `http://127.0.0.1:17865/?token=…` 链接能看到控制台 |
| 账号已登录 | `tg_list_accounts` 返回 `status: "ready"` |
| MCP 已接入 | 按「接入 AI」页的配置接入 `tg-agent` |
| 离线单元测试 | `.venv\Scripts\python.exe -m pytest -q` 全部通过（44 项） |

下文用 `<CH>` 表示测试频道（推荐公开频道 `telegram`）。首次解析后记下它的数字 ID `<ID>`，后续调用尽量使用 `<ID>`。

## 1. 工作流（v1.0 核心）

**作为 AI 测试者，从这里开始的每组测试都应先调用 `tg_start_workflow`，结束时调用 `tg_finish_workflow`。**

| # | 步骤 | 预期 |
|---|---|---|
| 1.1 | `tg_start_workflow(title="测试：读取频道")` | 返回 workflow_id；控制台「工作流」页左栏“进行中”出现该标题，并自动选中 |
| 1.2 | `tg_resolve_chat(chat="<CH>")` | 中间出现节点 ①「解析频道」，完成后显示结果摘要和耗时 |
| 1.3 | `tg_list_files(chat="<ID>", limit=5)` | 出现节点 ②，与 ① 之间有连线 |
| 1.4 | `tg_get_message(chat="<ID>", message_id=<1.3 中某个 message_id>)` | 出现节点 ③；③ 的徽标显示数据依赖数量，左侧有琥珀色弧线连到产出该 message_id 的节点 ② |
| 1.5 | 点击任意节点 | 右侧打开详情，显示完整参数 JSON 与结果 JSON；节点相关连线高亮 |
| 1.6 | 连续调用 3 次 `tg_tasks()` | **不产生新节点**；工作流头部显示“已查询进度 ×N” |
| 1.7 | `tg_finish_workflow(summary="读取测试完成")` | 状态变为“完成”，头部显示总结，流程末尾显示“已完成” |
| 1.8 | 点击标题改名并回车 | 名称保存，左栏同步更新 |
| 1.9 | 不调用 `tg_start_workflow`，直接调用 `tg_list_accounts` | 调用被归入“未命名工作流”（斜体显示），返回结果里带 `_hint` 提示应先开始工作流 |
| 1.10 | 左栏「日志」标签 | 显示系统、下载等原始事件流 |
| 1.11 | 运行 `.venv\Scripts\python.exe tests\workflow_demo.py` | 输出全部为 `ok`；控制台出现一条 4 步工作流，下载节点显示“已查询进度 ×2”和已取消的子任务 |

## 2. 只读查询

| # | 调用 | 预期 |
|---|---|---|
| 2.1 | `tg_list_dialogs(limit=10)` | ≤10 个对话，含 id、title、type |
| 2.2 | `tg_resolve_chat(chat="https://t.me/<CH>")` | 与用户名写法结果一致 |

## 3. 本地索引（不请求 Telegram）

| # | 调用 / 操作 | 预期 |
|---|---|---|
| 3.1 | `tg_index_status()` | 列出已索引的对话（第 2 节列过的文件已自动写入） |
| 3.2 | `tg_search_files(query="<2.5 中某个文件名里的词>")` | 能找到该文件；返回带 note 说明是离线搜索 |
| 3.3 | 控制台「文件库」：输入关键词搜索；按“按大小”排序 | 结果正确，可点链接或下载按钮 |
| 3.4 | `tg_index_chat(chat="<ID>")` | 返回 task_id；「任务 → 导出与索引」中出现索引任务并完成；再次调用时 `incremental_from` 大于 0（只扫新消息） |
| 3.5 | 若有两个已索引对话：`tg_compare_chats(chat_a=..., chat_b=..., by="name_size")` | 返回共有 / 仅 A / 仅 B 的数量与样例；控制台「文件库 → 对比」结果一致 |

> 3.4 对大频道会扫描很多消息，请选一个小频道，或跳过。

## 4. 下载与批准

| # | 调用 / 操作 | 预期 |
|---|---|---|
| 4.1 | `tg_download(chat="<ID>", message_ids=[<一个小文件>])` | 默认限额下直接 `queued: 1`；工作流节点下出现该文件并实时显示进度；完成后状态为“完成” |
| 4.2 | 检查返回的 path | 文件存在、大小一致，没有残留 `.part` / `.part.json` |
| 4.3 | 请用户把「设置 → AI 安全 → 超过多少 GB 需批准」临时改为 `0.001`，然后再请求一个文件 | 返回 `requires_approval: true`；工作流页顶部和节点内出现批准条；**请用户**点“拒绝” |
| 4.4 | `tg_tasks(task_ids=[...])` | 状态为 canceled；测试后请用户把限额改回原值 |
| 4.5 | 暂停 / 继续：下载一个 5～20 MB 的文件后立即 `tg_task_control(action="pause")`，再 `resume` | 暂停后速度归零；继续后从断点续传而不是从 0 开始 |
| 4.6 | 已下载过的文件再次下载 | 新任务状态为“已存在”（skipped） |

## 5. 订阅

| # | 调用 / 操作 | 预期 |
|---|---|---|
| 5.1 | `tg_watch(action="add", chat="<ID>", types=["video"], max_size_mb=5, interval_min=60)` | 返回带 `pending_approval: true` 的订阅和提示；控制台工作流页顶部出现订阅批准条，「订阅」页卡片标记“待批准”，导航有角标 |
| 5.2 | `tg_watch(action="resume", watch_id=...)` | 报错：需要用户批准（AI 不能自行启用） |

| 5.4 | 请用户在「订阅」页点删除（或 `tg_watch(action="remove", watch_id=...)`） | 订阅消失 |

## 8. 安全

```bash
curl -s --noproxy "*" http://127.0.0.1:17865/api/state
```
预期：`{"error":"unauthorized", ...}`

```bash
curl -s --noproxy "*" -H "Host: evil.com" http://127.0.0.1:17865/api/state
```
预期：`{"error":"forbidden host"}`

另外确认：
- `data/accounts.json` 里没有明文 api_hash（字段 `api_hash_enc`，值以 `dpapi:` 或 `keyring:` 开头）；
- 用浏览器直接打开 `http://127.0.0.1:17865/`（不带 token）时显示“需要访问令牌”页面。

## 10. v1.1 新功能

| # | 调用 / 操作 | 预期 |
|---|---|---|
| 10.1 | `tg_plan_download(chat="<ID>", message_ids=[<小文件>])` | 返回 file_count、total_size、needs_approval、estimated_seconds（无历史速度时为 null）；**不会**加入任何下载 |
| 10.2 | 先 `tg_download` 一个小文件，再立刻调 `tg_wait_tasks(task_ids=[...], timeout_s=120)` | 调用一直等待到任务完成才返回，`finished: true`；工作流里这次等待不新增节点，计入“已查询进度” |
| 10.3 | 对 10.2 已下载的同一文件再 `tg_plan_download` | `already_downloaded: 1`，skipped 里注明“已下载过” |
| 10.4 | 「文件库」搜索 10.2 的文件名 | 结果行有“已下载”标签 |
| 10.5 | 找一个有分卷压缩包（`.7z.001`、`.part1.rar`）的频道，`tg_list_files(..., limit=20)` | 返回 `archive_sets`，列出套名、卷数和缺失的卷；浏览页的文件表显示“分卷 N”标签 |
| 10.6 | 对其中一卷 `tg_plan_download(chat=..., message_ids=[<第 1 卷>])` | `added_archive_parts` > 0，file_count 等于整套卷数（只做预估，不要真的下载大文件） |
| 10.7 | 工作流页点「导出报告」 | 下载一个 .md 文件，包含标题、每一步的参数和结果 |
| 10.8 | 工作流页点「重跑」（选一个只有读取步骤的工作流） | 新出现一条“重跑：…”工作流，步骤依次执行；来源显示为 replay |
| 10.9 | 设置 → 限速改为 200 KB/s，下载一个 5 MB 左右的文件 | 速度稳定在约 200 KB/s；顶栏出现“限速”提示。测完改回 0 |
| 10.10 | 设置 → 下载时段设为当前时间之外（如现在 14:00，设 23:00–07:00），再下载一个文件 | 任务保持“排队中”，显示“等待下载时段”；顶栏显示“下载时段外”。测完清空时段 |
| 10.11 | 设置 → 下载目录改成不存在的盘符（如 `Q:\x`），再请求下载 | 立即返回清楚的错误“下载目录不可用……”，不会产生失败任务。测完改回 |
| 10.12 | 设置 → 勾选“桌面通知”，浏览器询问时允许；完成一个下载 | 系统弹出“下载完成”通知 |
| 10.13 | Windows：启动后看任务栏托盘 | 有橙色 TG Agent 图标；菜单可打开控制台、全部暂停、退出（退出后服务停止） |
| 10.14 | 观察数值显示 | 小于 1 KB 的速度/大小都显示为 `0 KB`，不会出现 `4.8e-21 B/s` 这类数字；没有意义的剩余时间不显示 |

> 10.9–10.11 会改动用户设置，测试后务必改回原值；10.5/10.6 只做预估，不要下载大文件。
